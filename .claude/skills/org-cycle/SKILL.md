# 案件サイクル（経営企画の手順書）

あなたは経営企画（進行役）です。`CLAUDE.md` の憲章に従って進めてください。

## 0. 状況把握
1. `org/goals.md`・`org/pipeline/backlog.md`・`org/owner-inbox.md`・`org/decisions/` を読む。
2. 進行中の案件（`org/pipeline/*/00-brief.md` のステータスが「進行中」「差し戻し中」）があれば、それを優先して続きから再開する。
3. オーナーが `owner-inbox.md` に回答・完了を書いた依頼があれば、関係する案件に反映する。

## 1. 起票
1. 引数でテーマが指定されていなければ、backlog から「目標への寄与 × 実現しやすさ」が最も高いものを1件選ぶ。
2. 次の連番で `org/pipeline/NNNN-slug/` を作り、`org/templates/00-brief.md` を元に `00-brief.md` を書く。
3. backlog の該当行を「着手済み（NNNN）」にする。

## 2. 部署への発注（順番に。並列にしない）
各部署を Agent ツールで呼ぶ。プロンプトには案件フォルダのパスと、特に注意してほしい点だけを書く。

| 順 | subagent_type | 期待する出力 |
|---|---|---|
| 1 | `researcher` | `01-research.md` |
| 2 | `merchandiser` | `02-products.md` |
| 3 | `channel-strategist` | `03-channel.md` |
| 4 | `editor`（フェーズA） | `04-outline.md` |
| 5 | `editor`（フェーズB） | `articles/*.html` と周辺更新 |
| 6 | `compliance-reviewer` | `05-review.md` |

各部署の完了ごとに、経営企画は次を行う:
- 出力ファイルを読み、書式末尾の**ゲート条件**を満たすか確認する。満たさなければ同じ部署に不足点を伝えて再実行（差し戻し1回とカウント）。
- 「前工程への質問・異議」欄を読む。前提を覆す異議なら該当工程へ差し戻す。軽微なら経営企画が回答を `00-brief.md` の「経営判断ログ」に書く。
- 03-channel で「新規記事より既存記事の強化」と判断された場合、フェーズBはリライトとして進める。

## 3. レビュー結果の処理
- **PASS** → 4へ。
- **REVISE** → 指摘ごとの差し戻し先の部署に 05-review.md を渡して修正させ、再度 `compliance-reviewer` を呼ぶ。
- **BLOCK** → 案件を「保留」にし、理由と代替案を `org/owner-inbox.md` に書いて終了。
- 同じ工程への差し戻しが2回を超えたら「保留」にしてオーナー判断を仰ぐ。

## 4. 仕上げ
1. `00-brief.md` のステータスを「オーナー承認待ち」にし、経営判断ログを締める。
2. 重要な判断があれば `org/templates/decision.md` で `org/decisions/` に記録する。
3. オーナー作業（提携申請、取材、リンク差し込み、SNS投稿）を `org/owner-inbox.md` に追記する。
4. 作業ブランチにコミットして push し、PRを作る。PR本文は `.github/pull_request_template.md` に従う。
   **マージはしない。**
5. 最後にオーナーへ、3〜5行の要約（何を作ったか、レビュー結果、オーナーにお願いしたいこと）を報告する。
