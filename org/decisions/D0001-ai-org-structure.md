# D0001: AI組織による運営体制の導入

- 日付: 2026-09-25
- ステータス: 採用（公開承認の部分は D0006 で改訂）
- 決定者: オーナー
- 関連案件: なし（体制づくり）

## 背景
アフィリエイトで月10万円を目指すにあたり、リサーチ・商品選定・媒体検討・執筆・レビューを
1つのAIに一度に任せると、根拠の薄い判断や規制違反が混入しやすく、品質が安定しない。

## 選択肢
1. 1つのAIセッションにまとめて記事を作らせる（現状）
2. 工程ごとに独立した部署（サブエージェント）に分け、書類で引き継ぎ、相互チェックとレビューで品質を担保する
3. 外部のAPI・サーバーで独自のマルチエージェント基盤を作る

## 決定
2 を採用。Claude Code のサブエージェント（`.claude/agents/`）＋手順書スキル（`/org-cycle`）＋
案件フォルダ（`org/pipeline/`）で運営する。公開の最終承認はオーナーがPRをマージして行う。
ヘルスケアAIダイジェストとは完全に分離する。

## 理由
- 追加のインフラや費用なしで始められ、全ての判断が書類とGitの履歴に残る。
- 前工程の検証・差し戻し・独立したレビューにより、1つのAIの思い込みがそのまま公開されるのを防げる。
- 法的責任を負うのは運営者なので、人間の承認ゲートを残す。

## 見直す条件
- 1案件を回すのにかかるオーナーの手間が、週2時間を大きく超える場合
- 3ヶ月運用して、レビューのPASS率や公開記事の検索順位が単独運用と比べて改善しない場合
