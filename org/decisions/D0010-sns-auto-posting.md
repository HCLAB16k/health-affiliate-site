# D0010: X（旧Twitter）への記事告知を自動投稿にする（マーケティング部の新設）

- 日付: 2026-09-28
- ステータス: 採用
- 決定者: オーナー（「yes, go ahead」「repost the existing 9 articles」）
- 関連: D0006（公開の委任）、D0003・D0005（クリニック系の扱い）、compliance-checklist 3章・4章

## 決定
- 部署「マーケティング部（`marketer`）」を新設。工程 06 として、記事ごとの X 投稿文を `org/social/queue/` に書く。
- 投稿文はレビュー部が記事と同じ基準で審査し、PASS したものだけを PR でマージする。**マージ後は GitHub Actions が指定日に自動で投稿する（オーナーの都度の承認は不要）**。D0006 の委任を X 投稿に広げる。
- 既存の公開記事9本も、1日1本ずつ告知する（オーナー判断）。
- 投稿の仕組みは状態を持たない: 毎日1回、投稿日が今日（日本時間）のものだけを投稿する。失敗・取りこぼしは経営企画が日付を付け直して再投入する。

## 投稿のルール（checklist 3章に追記）
- アフィリエイトリンクが描画される記事への投稿は「#PR」を付ける。
- クリニック系の記事（医療広告として扱う記事）の投稿は、記事URLと記事の論点のみ。クリニック名・料金・「無料カウンセリング」等を書かない（限定解除の要件①）。
- 効能・効果の表現、体験談、ランキング、「最強」等の最大級表現は書かない。記事の中立的な問い・論点を短く示す。
- X の設定で「自動化されたアカウント」のラベルを付ける（オーナー作業）。

## 秘密情報
- X の API キー4つは GitHub の Actions secrets にだけ置く（`X_API_KEY`・`X_API_SECRET`・`X_ACCESS_TOKEN`・`X_ACCESS_SECRET`）。リポジトリ（公開）・チャット・書類に書かない。
