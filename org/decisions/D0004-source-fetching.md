# D0004: 一次情報の原文は `.sources/` に取得し、部署が自力で取れるようにする

- 日付: 2026-09-27
- ステータス: 採用
- 決定者: 経営企画
- 関連案件: 0001（調整運転の振り返り④）

## 背景
クラウド環境で WebFetch が遮断され、リサーチ部・レビュー部が一次情報の本文を読めなかった。
0001 では経営企画が curl で取得して `.sources/` に置き、原文確認パスを別途発注して解消したが、工程が1つ増えた。

## 決定
- 原文は `.sources/`（Git管理外。著作物をリポジトリに入れない）に置き、`README.md` に一覧化する。
- researcher / merchandiser / compliance-reviewer の tools に Bash を追加し、curl での取得・テキスト化・grep に限って使わせる（職務定義に明記）。
- TLS検証の無効化（`curl -k`）は禁止。

## 理由
- 医療・健康情報は原文確認が品質の前提で、取得を経営企画に集中させるとボトルネックになる。

## 見直す条件
- WebFetch が使えるようになった場合（Bash の許可を外すか検討）
- `.sources/` はコンテナ終了で消えるため、再取得のコストが問題になった場合
