# D0019 KPI の体系・目標の見直し・可視化と週次の自動化

- 日付: 2026-10-13
- 決定者: 経営企画（オーナー指示「進捗がわかるように整えたい。KPI の設定、目標の見直し、可視化、自動化、諸々整理して。部署が必要なら検討して」）
- 関連: `org/kpi/README.md`（定義・目標・運用）、`org/kpi/targets.json`、`org/goals.md`、`scripts/kpi_dashboard.py`

## 決定
1. **KPI ツリー**を「作る → 届く → 稼ぐ → 運営」の4層で定義する。立ち上げ期は先行指標で判断する。
   - 作る: 記事数・収益の導線のある記事・使える提携
   - 届く: インデックス・検索表示・セッション
2. **目標の見直し**: 期を4つ（2026-11末／2026-12末／2027-03末／2027-09末）に分け、期ごとに数値の目標を置く（`targets.json`）。
   - 記事数は前倒しで進んでいるため上げた（2026-12: 20→38、2027-09: 55→70）。
   - 新たに置いた目標: インデックス・収益の導線・ASP クリック。
   - 最終目標（月10万円、2027-09）は変えない。
3. **可視化**: `scripts/kpi_dashboard.py` が作る KPI ボードを、claude.ai の非公開の Artifact で見られるようにする（URL はチャットで共有し、リポジトリには書かない）。
4. **自動化**:
   - 自動で取る指標: 記事数・導線・オーナー依頼・案件・X の予約。
   - 手入力の指標: Looker Studio の週次メール（オーナーの Gmail）を、毎週月曜の定期実行が読んで `weekly.csv` に転記する。
   - 定期実行は作業ブランチにコミットするだけで、main にはマージしない（マージは経営企画）。
5. **部署**: 新しい部署は作らない。分析部（analyst）が KPI の責任者を兼ねる（月次レポート・四半期の目標の見直し）。
   - 週次の転記とボードの更新は、定期実行（経営企画の代行）が行う。
   - 分析部は Gmail・Bash を持たないので、データの取り込みは経営企画側で行う。
6. **金額**: 収益の金額は、公開リポジトリにも KPI ボードにも書かない。件数と、目標の到達／未到達だけを書く（CLAUDE.md 6章）。

## 理由
結果指標（PV・収益）がまだほぼ0の段階でも、進み具合と詰まっている場所（今はインデックスと収益の導線）が一目で分かるようにするため。
