# SEO の担当と月次チェック（D0012）

## 担当（誰が何を持つか）
| 領域 | 担当 | 内容 |
|---|---|---|
| **SEO 全体の責任者** | 分析部（analyst） | 月次で Search Console の数値を読み、伸びる／落ちる記事、リライト候補、技術的な問題を `org/kpi/report-YYYY-MM.md` にまとめ、backlog に起票する |
| キーワード・検索意図・競合 | リサーチ部 | 各案件の `01-research.md` |
| 主キーワード・URL・内部リンク・計測計画 | プラットフォーム戦略部 | 各案件の `03-channel.md` |
| title・meta・見出し・本文 | 編集部 | 各案件の記事 |
| 表示の誇張・出典の確認 | レビュー部 | 各案件の `05-review.md` |
| 技術（sitemap・canonical・OGP・構造化データ・HTML骨格・GA4） | 経営企画 | `scripts/build_site.py` が全ページに自動で付ける（下記） |
| Search Console の操作（インデックス登録のリクエスト、数値の共有） | オーナー | 下記の月次チェック |

## 技術面（自動で入るもの。`python3 scripts/build_site.py`）
- 全ページ: `canonical`、Open Graph（og:title・description・url・image）、Twitter カード（大きい画像）。共有時の画像は `images/og.png`（文字なし）。
- 記事: 構造化データ（Article: 公開日・更新日・発行者「男の養生帖」・著者「男の養生帖 編集部」、BreadcrumbList）。トップ: WebSite。
- `sitemap.xml`: 全ページ＋記事・カテゴリの更新日（lastmod）。記事を足すと自動で入る。
- `robots.txt` はリポジトリ直下にあり `/health-affiliate-site/robots.txt` として配信されるが、Google が読むのはホスト直下（`https://hclab16k.github.io/robots.txt`）の robots.txt だけなので、クロール制御には使えない。sitemap は Search Console から送信済み（サイトマップの状態が「成功しました」かは月次チェックで確認）。
- 新しい記事: `scripts/site_data.json` に追加して build（CLAUDE.md 7章）。記事を更新したら `updated` を入れる。

## 月次チェック（オーナー → 分析部）
毎月初、Search Console で前月の次を確認して、チャットで伝える（画面のスクショでよい）:
1. **インデックス**: 「ページ」→ 登録されたページ数／されていないページと理由（サイトマップの状態が「成功しました」か）
2. **検索パフォーマンス**（過去28日）: 合計クリック数・表示回数・平均CTR・平均掲載順位
3. **ページ別**: 表示回数の多い上位10ページのクリック・順位
4. **クエリ別**: 上位10クエリ。「おすすめ」「ランキング」系が出ていないか（出たら、C02（`org/pipeline/candidates.md` のフッ素歯磨き粉の候補）や #27（`org/pipeline/backlog.md` の「セール時の紹介ページ」）の入口のサイン）
5. **新記事のインデックス登録のリクエスト**: 公開直後に URL 検査 →「インデックス登録をリクエスト」（1記事1分）
6. GA4 が入っていれば、ページ別の閲覧数と流入元（検索・X・直接）

## 分析部の判断の目安（小さいデータで断定しない。期間は経営企画の目安で、根拠のある基準ではない）
- 表示回数が多いのにクリックが少ない（CTR が低い）→ title・meta の見直し（誇張しない）
- 掲載順位が 11〜20 位 → 見出し・出典・内部リンクの追加（リライト）
- クリックはあるが記事内のクリックが無い → 商品枠の位置・文言（リンクがある記事のみ）
- 公開から2週間はインデックスの確認、1〜2か月で表示回数が付くか、3か月で順位・CTR からリライト判断（新記事）
- クリック数十件未満の変化は因果として断定しない

## 更新日の運用
- 記事の本文を変えたら、`scripts/site_data.json` の該当記事の `updated` を更新して build する（構造化データの dateModified、sitemap の lastmod、カードの「更新」日に反映）。体裁だけの変更（ナビ・head）では更新しない。
- リポジトリ直下の画像・SVG は配信される。作図の中間生成物は `org/brand/` に置く。
